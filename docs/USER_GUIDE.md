# voice input 使用与排错

适用平台：Windows 10/11 x64。此构建仍需真实 Windows/设备/服务验收；请先使用虚构文字在记事本测试。

## 1. 首次启动

1. 将便携 ZIP 解压到任意用户可写目录；安装 WebView2 Evergreen Runtime。
2. 普通权限运行 `voice_input.exe`。服务配置完整时托盘常驻；首次启动或配置未完成时打开设置。
3. 点击托盘图标或右键菜单“设置”，填写服务地址、模型并保存密钥。默认使用 ASR + LLM，不再提供离线 Mock。
4. 在记事本定位光标，按 `Ctrl+Alt+R`，再按一次；检查显示、中文/emoji、关闭取消，以及切换输入框后文字进入当前活动位置。

从托盘“退出”才能完全退出；关闭设置或浮窗只隐藏，活动任务会在浮窗关闭时取消。没有“自动发送”选项。

同一 Windows 用户会话只保留一个实例，重复启动直接退出，不激活旧窗口。退出或异常结束后系统自动回收锁，不需要删除锁文件。升级前请先退出旧实例。

## 2. 配置真实服务

### ASR 直通模式：先验证语音

> **协议选择：** 以下 `/audio/transcriptions` 与“不要使用聊天地址”的规则仅适用于 OpenAI-compatible multipart。MiMo ASR 请先选择 `mimo` 协议，使用本页第 7 节的完整 Chat Completions 端点；不要混用两种请求格式。

- 选择“ASR 直通”。实际采集麦克风，只使用 ASR，不调用 LLM。
- 刷新麦克风列表，选择默认或具体设备。Windows 设置中的麦克风隐私权限必须允许桌面应用访问。
- ASR endpoint 必须是**完整转录路径**，例如 `https://服务地址/v1/audio/transcriptions`。不要填入 `/chat/completions`。
- 填写厂商实际支持的模型；语言可留空或按服务要求填 `zh`。
- 保存设置，再在 ASR 密钥框输入 Key，点击“保存密钥”。保存后输入框立即清空，已有 Key 不回显。
- 可点击“测试连接”：发送 0.5 秒合成静音 WAV，仅验证协议，不录制你的麦克风，也不保证识别准确性。API 可能收费。
- 在记事本按快捷键开始真实录音；再次按下停止并识别。默认最多 120 秒，可设置 1–300 秒；到期自动停止处理。
- 录音短于约 0.3 秒或整体接近静音会拒绝上传。设备断开、权限不足或格式不支持时明确失败，不伪造识别。

音频在内存中转成 16 kHz、单声道、16-bit PCM WAV。支持原生 PCM16/24/32 或 float32 的常见共享模式设备；驱动、设备格式、线性重采样质量仍需实测。若服务不接受此 WAV 约定，本版本不会自动假定其他协议。

### 真实语义模式

- 选择“ASR + LLM”。
- 填写 Chat Completions 兼容服务的 base URL（通常以 `/v1` 结束）和实际模型名。程序追加 `/chat/completions`。
- 默认输出格式 `json_schema`；服务明确不支持时手动改为 `json_object`。不会自动重复请求尝试不同协议。
- 分别保存设置、LLM Key，按需测试连接。测试不启用搜索。
- 模型输出必须恰好包含字符串 `status/text/notice`：`insert` 才自动输入当前活动位置；`skip/clarify` 不改变输入框。
- JSON 非法、字段缺失/重复/额外字段、错误状态、截断回复、异常工具或超长正文均拒绝回填；保留 ASR 原文供复制。

真实 ASR+LLM 模式共用服务配置，通过两个快捷键选择用途：

| 用途 | 默认快捷键 | 模型负责什么 |
|---|---|---|
| 语音润色 | `Ctrl+Alt+R` | 默认修正语病、语境明确的成语错用及不当措辞，精简冗余并调整句式；不执行口述指令或回答问题 |
| AI 对话 | `Ctrl+Alt+A` | 理解并执行请求，生成写作、翻译、回答或代码等所需正文，必要时澄清 |

例如口述“帮我写一封请假邮件”，润色入口只整理这句话，AI 对话入口才生成邮件。润色用途不提供搜索工具，也不因缺少任务条件追问；即使 Exa 已开启，也不读取搜索凭据。只有明确的口述排版要求（如换行、另起一段）可作为格式指示处理。AI 对话只在用户明确要求写提示词时输出提示词，不再猜测目标应用而自动改为只整理请求。实际语义效果依赖所配模型，自动请求/schema 测试不能证明真实模型完全遵守这些规则。

### 界面语言

“输入”页提供“跟随系统”、简体中文和英文。默认跟随 Windows 的首个受支持界面语言，未匹配时使用英文；中文使用简体词典。选择后先预览设置页，点击保存才应用到桌面浮窗和托盘；关闭设置不会保存草稿。界面语言与 ASR 的识别语言独立。

未自定义时，内置业务提示词随已保存的界面语言选择等义版本，编辑器显示与实际请求一致；自定义提示词、背景、转录、模型回复和来源不翻译，也不因英文界面要求模型用英文回答。任务开始后保留该任务的规则和语音记录标签语言，后续保存不改写已有任务。

### 自定义提示词与设置草稿

设置分为“输入”“通用”“模型服务”“提示词”“联网与预算”五区：宽窗口使用左侧分类栏，宽度不超过 640px 时切换为顶部分类；底部始终可以保存或关闭。切换分类、调整窗口宽度不丢失当前编辑，只有内容区滚动。侧栏使用上下键、顶部分类使用左右键切换，Home/End 到首尾；提示词用途始终使用左右键。

- “提示词”中可分别编辑语音润色、AI 对话的业务规则，例如改写程度、语气和组织方式。默认润色允许中度重写，但仍保留事实、数字、人物、时间、否定、条件、因果、责任主体、立场、情绪及不确定性；歧义不靠猜测消除。
- 每份提示词最多 16000 个 Unicode 字符，与背景信息分别保存。自定义规则只替换对应用途的业务段，不替换固定用途边界、JSON 输出协议或工具权限；不能借此把润色变成执行请求。
- 未自定义时显示实际内置规则，切换界面语言时默认内容随之更新；恢复默认或保存全空白内容表示继续使用内置默认，不冻结旧默认版本。已有自定义内容逐字保留；“恢复默认”只修改当前草稿，覆盖编辑前会确认，仍需点击“保存设置”。
- 配置读取完成前不能编辑；读取失败时禁用保存与凭据操作。保存失败保留草稿；等待保存期间继续编辑的内容不会被晚到响应覆盖，需要再次保存。
- 连接测试使用已保存的配置与密钥；相关服务字段、有效代理配置或密钥草稿未保存时，先保存再测。背景、提示词及每轮预算的编辑不阻断协议测试。LLM 测试使用固定默认规则且不启用搜索，不验证自定义提示词的实际效果。
- 旧配置缺少新字段时在内存补全默认，不自动改写文件。配置实际 JSON 总容量上限为 512 KiB；保存后包含新字段，旧版程序可能无法读取，降级前应备份。

默认润色质量的人工验收案例见 [DICTATION_QUALITY_CASES.md](DICTATION_QUALITY_CASES.md)；离线测试不等同于真实模型效果验收。

### 通用设置

代理默认开启并跟随系统；自启动、自动复制和录音静音开关默认关闭。修改后需点击“保存设置”，打开旧配置只在内存补全默认，不自动改写文件。

- **代理**：关闭时强制直连；开启时选择跟随系统或手动配置协议、主机和端口。详见第 6 节。

- **Windows 开机自启动**：当前用户登录 Windows 后运行本程序，普通模式使用当前用户启动项，无需管理员权限。关闭此开关也会清除管理员子选项。
- **自启动时以管理员身份运行**：只在自启动开启后可选，通过当前用户的登录计划任务以最高可用权限运行。首次设置或切换需要系统 UAC 授权；仅支持当前账户自身提权，不支持输入另一管理员账户的凭据代为注册。保存不会立即重启或提升当前实例，权限变化从下一次登录启动生效。正常手动启动仍使用普通权限，不关闭 UAC、不保存管理员凭据。
- **自动复制结果**：得到有效 ASR 原文后立即写入剪贴板，得到有效最终正文后再替换。即使模型服务失败、正文不支持自动输入或输入失败，也保留已得到的文字；澄清问题、错误提示和非法模型响应不作为最终正文复制。剪贴板被占用时会单独提示复制失败，不阻止自动输入。开启后单行结果也会替换剪贴板；系统历史或同步工具可能保留这些内容。
- **结果显示时长**：默认 30 秒，可设 1–3600 秒。后续任务使用新时长，不重置已经显示结果的倒计时；鼠标移入、点击或滚动仍保持到手动关闭，等待澄清时不倒计时。
- **录音时静音系统声音**：录音前静音默认播放设备，停止、取消、时长结束或录音初始化失败时恢复原静音状态；原本已静音则保持静音，不修改音量大小和麦克风。补充录音同样适用，识别和生成阶段不继续静音。此功能不保证屏蔽其他播放设备或外部环境声；若驱动失去响应、进程被强制结束或恢复失败，请手动检查系统音量。

便携程序移动位置前，请先在原位置关闭自启动并保存；移动后从新位置重新开启并保存。原注册路径失效或任务被外部修改时，不自动覆盖未知任务，需要先在 Windows 中检查清理本应用的旧注册。普通设置保存不反复请求 UAC。注册失败或取消授权时不提交新配置；若配置保存失败后的系统注册补偿也失败，会明确提示自启动状态可能已改变，需要重新检查保存。

### 回答 AI 对话的澄清问题

1. 模型返回“需要补充信息”时，浮窗显示具体问题，例如“你指的是车手冠军，还是车队冠军？”。此时不会自动输入，也不会在 30 秒后隐藏。
2. 再按一次 **AI 对话快捷键**（默认 `Ctrl+Alt+A`），或点击“语音补充”，开始录制回答；说出“车手冠军”等补充信息后，再按同一快捷键或点击“结束补充”。按钮沿用非激活浮窗，不需要切换焦点或打开文字输入框。
3. 程序结合原始请求和历次问答继续处理，不把短回答当作独立任务。仍有关键歧义时可以再次提问；只有返回最终正文后才输入完成时的当前活动位置，不按 Enter。
4. 补充录音启动失败、识别失败或没有有效内容时，保留问题，允许重新录制。关闭浮窗会取消整项任务；下次快捷键从新任务开始。

每项任务最多接受 8 次补充，原始请求和问答正文合计最多 128 KiB。等待回答不消耗处理超时；每次结束录音后分别执行既有处理时限。最终结果恢复已保存的显示时长（默认 30 秒）；若鼠标已移入、点击或滚动浮窗，则保持到手动关闭。原始语音、问题和回答仅保留于当前任务内存，语义处理时会发送给配置的 LLM；不写入背景信息或本地历史。


### 可选 Exa 搜索

- 默认关闭；仅 AI 对话在用户启用并单独保存 Exa Key 后提供唯一工具 `search_web`。
- Exa 地址固定为 `https://api.exa.ai/search`，不能配置成任意工具或任意搜索后端。
- `instant/fast` 可选，搜索超时只能 8–15 秒。每轮预算在“联网与预算”中设置：

  | 参数 | 默认 | 范围与含义 |
  |---|---|---|
  | 最大搜索次数 `exa.max_calls` | 2 | 1–8；每个 query 各算一次实际搜索尝试 |
  | 最大工具轮数 `llm.max_tool_rounds` | 2 | 0–8；一次模型回复中的整批 tool_calls 算一轮 |
  | 模型请求上限 | 3 | 派生为工具轮数 T+1，不额外配置或隐性追加收尾请求 |

  同一批两个查询占用 1 工具轮、2 搜索次数；工具轮数为 0 时不提供搜索工具，也不读取 Exa 密钥。每次补充语音开始新的处理轮次，预算重新计算，**不是整个多轮任务的累计费用上限**。超预算或非法工具批次整体拒绝，不部分执行，也不自动重试。每轮处理超时不会因调高预算自动延长。
- 只发送模型提出的必要查询，不在请求中自动附加完整转录或背景。网页文字只是不可信证据，不开放执行能力。
- Exa 失败直接安全终止并保留原文；不会把错误假装成搜索成功。无证据时提示模型澄清，不凭空确定天气等时效事实。
- 浮窗可查看搜索来源标题、URL、日期。显示为文字，不自动打开网页。

### 浮窗外观与尺寸

浮窗固定在工作区右下角，按内容阶段调整尺寸：普通录音/处理约 400×240 DIP，有澄清问题约 400×400 DIP，完成或失败后存在正文/原文时约 400×560 DIP。补充录音和处理期间保留问题区，不提前缩回紧凑态；小工作区按可用空间缩小。音量声波来自真实录音电平，不表示频谱或虚构处理进度。

原文和正文为空时不显示占位区；有内容时可滚动回看，“设置 / 关闭 / 复制”操作集中在底栏，补充按钮位于上一行。处理中已有原文也可复制，复制反馈不会覆盖错误说明；长错误仍可在紧凑态滚动查看。

较新 Windows 11 尝试在窄外缘使用系统材质和小圆角，所有文字和按钮保持实底。Windows 10、系统不支持、关闭透明效果或系统退回实色时，使用清晰的不透明外观；圆角和材质不保证持续可见。不会为了玻璃效果激活浮窗。

## 3. 背景与隐私

背景信息为一个可留空的大文本框，最多 16000 字，可自行填写称呼、术语、表达偏好和任务背景。真实语义模式将这段文字与本机当前时间提供给配置的 LLM，不读取目标窗口全文、网页或聊天记录。旧配置中的姓名、昵称、城市、时区和自定义背景会在内存中合并为可编辑文字；打开配置不会自动重写文件，保存后使用单一背景字段。

配置文件：**`voice_input.exe` 所在目录的 `config.json`**，不是当前工作目录或快捷方式所在目录。

- 同级文件存在时只使用它；格式非法、不可读、目录或失效链接会明确报错，不会用旧文件覆盖。
- 仅在同级文件缺失时，从旧 `%APPDATA%\voice_input\config.json` 校验并迁移。旧文件字节不变，作为备份保留；迁移成功后只保存同级文件，不双向同步。迁移期间若目标已出现，读取目标而不覆盖。
- 两处均无文件时使用默认值，点击保存后才创建同级文件。程序目录必须可写；迁移或保存失败时保留原数据，不提权、不回退到 AppData。可将程序移至用户可写目录后重试。
- 复制配置可携带背景、提示词和服务地址等设置，不能携带密钥；背景等私人内容也应自行妥善保管。发行 ZIP 不打包旁边的配置文件。

密钥：当前 Windows 用户的 Credential Manager，固定目标名 `voice_input/asr`、`voice_input/llm`、`voice_input/exa`。Key 不进入 JSON、LLM prompt、日志或诊断信息；同一 Windows 用户下的恶意软件不在安全存储可防御的边界内。

默认不落盘音频、转录、结果或历史。多行自动粘贴、手动复制及已开启的自动复制会将文字放入系统剪贴板；若开启 Windows 剪贴板历史、同步或第三方剪贴板管理器，系统或其他软件可能保留/同步这些文字，不属于应用自身“不保存历史”的范围。浮窗始终置顶且不激活。任务结束后未交互则按设置时长保留（默认 30 秒）供复制；鼠标移入、点击或滚动后，持续显示直到手动关闭。新任务会清空旧文本并重置常驻状态。程序不再收集或显示耗时统计。WebView2 自身的用户数据/缓存由运行时管理，生产隐私检查仍需实测。

## 4. 自动输入与安全降级

**程序不检查焦点、原窗口、控件身份或密码框属性。** 录音与处理不依赖输入框检查；结果提交到处理完成时的当前活动位置，不恢复原焦点。请自行确认当前活动位置适合接收文字。

- 切到其他应用或同窗另一个输入框，结果将输入新的活动位置。
- 系统权限或输入拦截仍可能导致失败；不要为兼容性而提权。
- 单行使用单批 Unicode `SendInput`，中文和 emoji 由 UTF-16 代理对提交。单行和多行均最多 8000 字（CRLF 规范成 LF 后计数）。
- 多行支持 LF/CRLF、空行和缩进空格，写剪贴板时使用 Windows CRLF，再提交一次 Ctrl+V。**多行结果会替换剪贴板，不自动恢复原内容**，避免目标异步粘贴读到旧数据；已有富文本/图片不做冒险备份与恢复。
- 未开启自动复制时，单行自动输入不接触剪贴板；手动点击“复制”也会替换剪贴板。
- 程序不模拟 Enter/Shift+Enter，不逐行敲键。目标控件必须支持多行粘贴；单行输入框可能折叠换行，终端或特定应用也可能自行执行粘贴内容，请自行确认目标。
- Tab、孤立 CR、其他控制字符或异常文本不自动输入，全文保留供复制。剪贴板被占用或写入失败时不提交粘贴。
- 如果部分输入已提交，不自动重试；先检查目标，避免重复粘贴。

最终正文在“已输入”或已有正文的“输入未完成”状态出现时，会自动滚动到正文尾部，不定位到下方来源列表末尾。之后可自行向上查看 ASR 原文，倒计时、保持显示、复制反馈和重复状态不再抢滚动；新任务重新定位。浮窗仍不激活、不改变输入位置。

“已输入”表示系统接受了事件，不是目标控件的内容确认。当前策略不阻止提交时的焦点变化；请在自己的应用完成验证后再日常使用。

## 5. 快捷键、超时与配置失败

用同一种快捷键按一次开始、第二次停止，不支持按住/松开。录音、处理或等待澄清期间，另一用途的快捷键只提示先结束/取消当前任务，不会停止录音、切换用途或另开任务。可在设置中分别修改两键，不能使用等价组合；Ctrl+V 保留给多行粘贴，不可设为录音键。支持两键互换；新组合无效、占用或保存失败时旧配置保留，若系统解绑/回滚异常会明确提示重启。成功保存后下次任务使用新配置；未完成任务请先取消再保存。

旧配置的 `hotkey` 保留为润色键，缺少 `ai_hotkey` 时在内存补充 `Ctrl+Alt+A`；若恰好与旧键相同，则补充 `Ctrl+Alt+Shift+A`。打开配置不重写文件，保存后才写入新字段；旧版程序的严格解析可能不支持新字段，降级前请备份。ASR 直通只作录音/转录诊断，AI 对话入口会提示切换到真实 ASR+LLM 模式，不会伪装成已执行请求。

单次 ASR/LLM 超时可设 5–180 秒；每轮处理超时 10–300 秒，从该轮停止录音起计时。取消/超时会禁止迟到结果回填；已提交的键盘输入不能撤回。取消也不能撤回已上传到服务的数据或已经发生的计费。

配置文件非法或未知版本时程序显示启动错误并退出，不擅自覆盖文件。请先备份并修复 EXE 同级的 `config.json`。如需彻底重置，先退出程序，备份并移开同级配置和旧 `%APPDATA%\voice_input\config.json`；仅改名同级文件可能再次导入旧配置。旧 `mode:"mock"` 会在内存中迁移为 `live`，不改写原文件。安全凭据与配置文件独立，改名配置不会删除 Credential Manager 中的 Key。

## 6. 代理与故障定位

在“通用 → 代理”中选择连接方式，修改后点击“保存设置”。ASR、LLM、Exa 和连接测试使用相同的代理设置。

| 应用设置 | 实际行为 |
|---|---|
| 关闭代理 | 直接连接，不使用代理 |
| 开启，跟随系统（默认） | 使用系统代理设置 |
| 开启，手动代理 | 使用填写的代理协议、主机和端口 |

所有模式下，本机 `localhost/127.0.0.1/::1` 目标均直连。手动主机字段只填独立主机名或 IP 地址，端口另填 1–65535 的整数，不含协议前缀、凭据或路径；IPv6 可以填写裸地址或完整方括号形式。

切换模式或关闭代理会保留已填写的手动配置。修改后请先保存，再测试连接。

代理配置失败时会提示错误，不会自动切换为直连。当前不支持代理身份验证。

- 401/403：检查对应服务 Key、模型权限及账户。
- 429：检查额度/限速；本版本不盲目重试。
- 5xx：服务不可用；保留原文后稍后重试。
- 请求不支持：检查路径、模型和结构化输出格式。地址禁止 URL 用户名、查询参数和片段，避免把密钥写入配置 URL。
- 麦克风不可用：检查隐私权限、驱动、设备是否拔出和其他应用独占。初始化等待最多约 10 秒；无响应 COM 调用不能强杀，可能需要退出并重启。
- 只读预览：浏览器预览不支持录音、保存设置或连接服务；请运行桌面程序使用这些功能。
- 无窗口：正常启动后程序在系统托盘运行。若托盘图标也未出现，请确认程序包已完整解压，并已安装 WebView2 Evergreen Runtime。源码构建问题参见[开发指南](DEVELOPMENT.md)。
- unsigned/SmartScreen：此构建未签名；核对来源与 SHA-256，不关闭安全防护或提升权限绕过拦截。

本版本没有安装包、更新器或 WebView2 自动安装引导。无开发环境机器启动、多屏/DPI、输入法、睡眠恢复与应用兼容性见测试矩阵，当前仍待真实 Windows 回归。

## 7. MiMo ASR 配置补充

MiMo 使用 JSON Chat Completions 音频协议，不是 multipart 文件上传。设置页中明确选择协议；切换协议只改变占位示例及语言约束，不会覆盖已填的地址、模型或语言。

| 字段 | MiMo 填写值 |
|---|---|
| ASR 协议 | `MiMo ASR`，配置值 `mimo` |
| 完整 endpoint | `https://api.xiaomimimo.com/v1/chat/completions` |
| 模型 | `mimo-v2.5-asr` |
| 语言 | `zh`；也支持留空、`auto`、`en` |
| 密钥 | 在 ASR 密钥框单独保存对应 MiMo Key |

程序将内存 WAV 编成 `input_audio` Data URL，非流式识别，读取 Chat Completions 的正文。为了保守满足官方 Base64 大小上限，发送前检查 Data URL 不超过 10,000,000 字节；过长音频明确失败，不截断或自动重试。默认 120 秒的 16 kHz 单声道 PCM16 录音在该编码上限内，设置到 300 秒不保证能上传。

- 不要填写 LLM 网关地址来替代 MiMo ASR 地址，也不要给 MiMo 协议填写 `/audio/transcriptions`。
- 保存顺序仍为：地址/模型/协议设置 → 单独保存 ASR Key → 按需测试连接。测试连接上传合成静音，仅验证协议，不代表识别质量。
- 通过环境变量提供测试凭据，**不等于写入应用凭据库**。桌面程序仍从 Windows Credential Manager 读取 Key，不自动导入环境变量；测试环境配置与应用设置相互独立。
- 旧配置没有 `asr.provider` 或值为空时继续使用原 multipart 协议；新设置保存后包含 provider，旧版程序的严格配置解析可能无法读取，降级前请备份配置。

协议依据：MiMo 官方语音识别文档 `https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/Speech-Recognition`。
