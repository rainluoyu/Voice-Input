# 安全检查范围

## 可复现检查

先完成[开发指南](DEVELOPMENT.md)中的构建和普通回归，再按需要执行：

```bash
./scripts/security.sh
```

该脚本运行 npm 依赖审计，并用固定版本的 `govulncheck` 扫描已有 `bin/voice_input.exe`。它不重新构建，也不启动 Windows 程序、录音、读取系统凭据或调用 ASR/LLM/Exa。

审计会访问外部数据库，首次运行可能下载工具。应使用实际执行侧 `PROXY_URL` 传递代理；离线环境不能将未执行的扫描记为通过。漏洞数据库、依赖和构建变化后，旧扫描结果不能作为当前安全保证。

## 发布前内容检查

- 审阅暂存文件及公开提交历史，排除配置、环境文件、密钥、音频、私人/未审核截图、原始服务报告、代理工作目录和私人部署资料。仅 `docs/images/en/` 与 `docs/images/zh-CN/` 中显式列入白名单的六张虚构数据图例外。
- 不在命令行参数、URL 用户信息或查询参数中放密钥，不将服务配置或正文写入日志。
- 检查实际 ZIP，而不只检查源码目录；打包必须使用显式白名单并保留第三方许可。
- 确认二进制由当前源码使用 `-trimpath` 重建，核对 SHA-256，不运行来源不明的文件。
- `.gitignore` 不影响已跟踪文件或旧历史；删除文件或新增提交也不能清除祖先提交中的敏感内容。

## 自动测试覆盖的属性

本地 fixtures 覆盖严格 JSON 输出、用途隔离、工具白名单和预算、重定向拒绝、错误脱敏、取消与迟到结果隔离、XSS 文本渲染、密钥不回显，以及只读预览不发真实请求。它们不构成全面安全审计。

## 不涵盖

- Windows GUI、驱动、WebView2、权限、焦点和原生凭据存储的实际安全行为。
- 真实模型的语义忠实性、事实判断或网页提示注入抵抗能力。
- 未公开漏洞、恶意本机软件、同一 Windows 用户下的凭据窃取。
- 安装、签名或 SmartScreen 体验；构建未签名，不能通过关闭防护或提升权限绕过拦截。

输入和剪贴板风险见[使用指南](USER_GUIDE.md)，实机用例见[测试矩阵](TEST_MATRIX.md)。任何静态扫描都不能证明绝不存在秘密或可利用漏洞。
